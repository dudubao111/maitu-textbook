## 二、实验目的

1. **掌握数字教材的组织方法**：理解并实践"章节目录—正文分节—代码与讲解结合—章节小结与练习—前后跳转"的数字教材结构。

2. **掌握静态站点生成技术**：使用 MkDocs + Material for MkDocs 从 Markdown 源码构建可响应的数字教材网站。

3. **完成面向真实教学场景的内容建设**：独立设计并编写 8 章、共 17 节的中小学信息科技竞赛（Python 算法与程序设计）教材内容，含学习目标、知识讲解、案例分析、代码实践、本章小结与练习。

4. **掌握基本的工程规范**：使用 Git 进行版本管理，掌握本地预览、静态构建与 GitHub Pages 部署流程。

5. **建立"技术选型需先验证环境"的工程意识**：在动手前实测运行环境与网络条件，而非假定依赖一定可用。

## 四、实验原理与相关理论

### 4.1 静态站点生成（SSG）

静态站点生成器把 **Markdown 源文件 + 配置** 编译成 **纯 HTML/CSS/JS**。
相比动态网站，它具有**无后端、易部署、加载快、易版本管理**的特点，非常适合教材类内容型网站。

### 4.2 技术组件的作用

| 技术 | 作用 |
|---|---|
| **MkDocs** | 静态站点生成器，负责解析 Markdown、套用主题、生成 HTML |
| **Material for MkDocs** | 主题，提供导航、搜索、代码高亮、提示组件、响应式布局 |
| **Markdown** | 教材正文源码格式，纯文本、易读写、便于 Git 管理 |
| **Git** | 版本管理，记录内容迭代过程 |
| **Python** | 教材中示例代码使用的编程语言 |

### 4.3 参考设计的分析

实验前分析了《Hello，算法》数字教材平台，提炼出可借鉴的设计思路（**仅借鉴思路，未复制其内容、配图、代码与品牌标识**）：

| 设计要点 | 本项目的实现方式 |
|---|---|
| 章节目录与分级导航 | MkDocs 侧边栏三级导航 + 章导学页 + `navigation.indexes` |
| 教材正文与知识点分节 | 每章拆为"章导学 + 2—3 个知识点页面" |
| 代码示例与知识解释结合 | 代码块 + 紧随其后的逐点解释 + 可运行输出示例 |
| 适合在线阅读的排版 | Material 主题 + 自定义 `extra.css` 调整字号、行距、间距 |
| 章节小结与练习 | 每章末节含"本章小结"（admonition）+ "练习与参考"（可折叠答案解析） |
| 前后章节跳转 | 页脚手动跳转链接 + Material 内置 `navigation.footer` |
| 统一的主题风格与响应式布局 | 统一主色与卡片样式；CSS 媒体查询适配移动端 |

| 2 | 计算思维与问题分解 | 建立"先想清楚再动手"的思维 |
| 3 | 变量、数据类型与输入输出 | 语法入门第一块地基 |

**统一页面结构**：学习目标 → 知识讲解 → 案例分析 → 代码实践 → 本章小结 → 练习与参考。

**内容准确性核查（重要）**：在撰写第 1 章时，通过检索官方信息发现并修正了一处**关键事实误差**——
CSP-J/S 与 NOI **只接受 C++ 提交，不支持 Python**，且广东省**不设个人报名**。
据此调整了教材定位表述，在首页、第 1 章、第 8 章补充了明确说明与 Python→C++ 迁移路线，
避免误导学生。

## 七、问题与解决方法

| 序号 | 遇到的问题 | 原因分析 | 解决方法 |
|---|---|---|---|
| 1 | `pip install mkdocs-material` 报 `No matching distribution found` | PyPI 官方源在当前网络不可达 | 换用阿里云镜像 `-i https://mirrors.aliyun.com/pypi/simple` |
| 2 | 换清华镜像仍失败 | 该镜像同样不可达 | 逐个测试镜像源，确认阿里云可用后固定使用 |
| 3 | 主题默认字体可能加载失败 | Material 默认从 Google Fonts 取字体，国内网络存在风险 | 配置 `font: false`，改用系统字体栈 |
| 4 | Mermaid 流程图可能不渲染 | Mermaid 依赖外部 CDN，国内可达性未验证 | 放弃 Mermaid，改用表格与文字流程图，**保证离线可用** |
| 5 | `pip` 安装时写入 `.venv` 内 `.icons` 隐藏目录被拒 | 沙箱策略限制写入隐藏目录 | 在沙箱外重试安装 |
| 6 | 教材原先定位"对标 CSP-J"不准确 | CSP-J/S 只接受 C++，不支持 Python | 检索官方信息核实后，修正定位表述并补充 Python→C++ 迁移路线 |
| 7 | 豆包讨论记录链接无法读取 | 页面需登录 | **如实说明未读取，不猜测内容**，改为通过交互确认关键决策 |

## 八、实验总结与反思

### 8.1 完成的工作

本实验完成了一个**真实可运行**的数字教材平台原型：以 MkDocs + Material for MkDocs 为技术路线，
建成含 1 个首页、8 章正文（24 页）、4 个附录页、共 29 个页面的静态教材网站，
并配套完成技术设计文档、实验报告与部署配置。

### 8.2 主要收获

1. **技术选型必须建立在实际环境探测之上。** 若照搬教程，实验会卡在第一条 `pip install` 上。
   "先探测、再选型"是本实验最有价值的经验。

2. **数字教材的核心是结构，不是视觉。** 章节目录、正文分节、代码与讲解结合、
   章节小结与练习、前后跳转——这些结构性的设计，比配色和动画更能决定阅读体验。

3. **内容的准确性优先于工作量。** 关于 CSP-J/S 语言要求的核查说明：
   教材内容涉及真实的竞赛规则时，**必须核实官方信息**，否则会误导学生。

4. **如实说明比"看起来完整"更重要。** 对无法读取的参考资料、
   无法代为完成的部署环节，均在报告中明确标注，而不做任何猜测。

### 8.3 不足与改进方向

| 不足 | 改进方向 |
|---|---|
| 尚未完成线上部署 | 待获取 GitHub 账号凭据后执行 `mkdocs gh-deploy` 或启用 Actions |
| 未实现交互式在线判题 | 可后续接入轻量在线运行环境或外链练习平台 |
| 插图以文字与表格为主 | 可在不依赖 CDN 的前提下补充本地 SVG 图示 |
| 实验报告为通用框架 | 若课程提供《创客教育》专用模板，按文末对应关系替换 |
| 教材内容可继续扩充 | 可增加真题解析、进阶算法（贪心进阶、简单动态规划）等章节 |

### 8.4 心得体会

本次实验最大的体会是：**做一个"能跑起来的东西"，和做一个"看起来不错的东西"，
难度差别很大。** 前者需要面对真实的环境、真实的报错、真实的限制。
正是在解决镜像源、字体、沙箱权限、事实核查这些具体问题的过程中，
才真正理解了"工程"二字的含义。

作为教育技术学专业的学生，这次实践也让我更清楚地看到：
**技术是手段，教学才是目的。** 一个数字教材平台的价值，最终取决于它的内容能否
让一个零基础的学生真正学会——而不是它的页面有多漂亮。
