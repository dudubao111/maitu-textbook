## 四、阶段四：构建与校验（错误与修复集中区）

### 4.1 ❌ 错误 2：首次构建失败（依赖尚未装完）

```bash
./.venv/Scripts/python.exe -m mkdocs build
```

**现象**：构建报错，`material` 主题无法加载。

**原因**：`mkdocs-material` 的安装尚未完成（解包中），依赖不完整。

**修复**：等待安装结束后重试。

**修复后结果**：构建成功，但出现 1 处链接警告。

### 4.2 ❌ 错误 3：首页与章导学页卡片链接路径错误

**现象**：构建时报告链接警告。

**原因**：自定义 HTML 卡片中的链接写成了站点绝对路径形式（如 `../map/`），
而 MkDocs 需要的是**相对于当前 Markdown 文件的源文件路径**。

**修复**：将卡片链接改为源文件相对路径形式：

```html
<!-- 修改前 -->
<a class="mt-card" href="../map/">…</a>
<!-- 修改后 -->
<a class="mt-card" href="map.md">…</a>
```

**验证**：修正后 `mkdocs build --strict` 无链接警告。

> 经验：Markdown 内的普通链接与自定义 HTML 内的链接，路径解析规则一致，
> 但**写惯了站点绝对路径**容易出错。`--strict` 模式是发现此类问题的唯一可靠手段。

### 4.3 ❌ 错误 4：Mermaid 流程图依赖远程 CDN

**现象**：章节知识地图最初使用 Mermaid 流程图，但渲染依赖远程 CDN。

**风险**：国内网络与离线环境下 CDN 可能不可达，导致图示区域空白。

**修复决策**：**主动放弃 Mermaid**，改用纯 Markdown 表格 + 文字流程表达知识结构。

**理由**：本项目的核心要求之一是"能在本地稳定演示"。图表美观的重要性低于"离线可用"。
放弃后所有图示均为纯 Markdown，无任何外部依赖。

### 4.4 严格模式构建（最终校验标准）

```bash
./.venv/Scripts/python.exe -m mkdocs build --strict
```

**结果**：`Documentation built in 2.94 seconds`，**零警告、零错误**，退出码 0。

> 说明：终端会输出一段 Material 官方关于 MkDocs 2.0 的提示信息，这是**上游团队的通告，不是本项目的警告**，不影响构建结果。

## 五、阶段五：内容缺陷复查与修复

本阶段为**交付后自查**，发现并修复了 4 处问题。

### 5.1 ❌ 错误 5：代码块数量统计方法错误（数据失真）

**现象**：初次统计代码块数量时，使用：

```bash
grep -rc '```' docs --include=*.md | awk -F: '{s+=$2} END {print s/2}'
# → 得出 218
```

**该结果错误**。原因：`grep` 会匹配**行内出现的**三个反引号以及缩进代码块，导致计数虚高。

**修复**：改用精确统计"带语言的开始围栏"：

```bash
grep -rc '^```python' docs --include=*.md | awk -F: '{s+=$2} END {print s}'
grep -rho '^```[a-z]*' docs --include=*.md | sort | uniq -c | sort -rn
```

**正确结果**：

```
76  ```python
72  ```text      （运行输出对照）
 1  ```cpp
 1  ```bash
```

即 **76 段 Python 代码块 + 72 段运行输出对照**。首页统计数字据此由"30+"更正为 **76**。

### 5.2 ❌ 错误 6：第 5—7 章实践任务编号重复（影响 10 处）

**现象**：同一章的不同小节文件中，实践任务编号各自从 1 开始，导致重复：

| 原编号 | 重复位置 |
|---|---|
| `5-1` / `5-2` | `list.md` 与 `string.md` **各出现一次** |
| `6-1` / `6-2` | `define.md` 与 `recursion.md` **各出现一次** |
| `7-1` / `7-2` | `enum.md`、`search-sort.md`、`recurrence.md` **各出现一次** |

**影响**：教师按编号布置作业、学生按编号对照答案时会对不上号，属实质内容缺陷。

**修复前先做安全检查**（避免改出断链）：

```bash
grep -rn "任务 [0-9]-[0-9]" docs/
```

确认任务编号**仅出现在 `##` 标题行**，正文、附录与 `answers.md` 中**均无交叉引用**，因此改动无副作用。

**修复**：重排为章内连续编号：

| 文件 | 原编号 | 新编号 |
|---|---|---|
| `05-liststr/list.md` | 5-1 / 5-2 | 5-1 / 5-2（不变） |
| `05-liststr/string.md` | 5-1 / 5-2 | **5-3 / 5-4** |
| `06-func/define.md` | 6-1 / 6-2 | 6-1 / 6-2（不变） |
| `06-func/recursion.md` | 6-1 / 6-2 | **6-3 / 6-4** |
| `07-algo/enum.md` | 7-1 / 7-2 | 7-1 / 7-2（不变） |
| `07-algo/search-sort.md` | 7-1 / 7-2 | **7-3 / 7-4** |
| `07-algo/recurrence.md` | 7-1 / 7-2 | **7-5 / 7-6** |

**验证**（输出为空即通过）：

```bash
grep -rho "任务 [0-9]-[0-9]" docs/ | sort | uniq -d
```

全站现为 `1-1` 至 `8-2` 共 **24 个编号，连续且唯一**。

## 十、本实验的经验总结

1. **技术选型必须建立在实际环境探测之上。** 若照搬教程，实验会卡在第一条 `pip install` 上。
   "先探测、再选型"是本实验最有价值的经验。
2. **`--strict` 模式是质量守门员。** 链接错误、配置错误只有它能可靠暴露。零警告通过才可标记为完成。
3. **统计类数据必须用精确的统计方法，并复核。** 本次因 `grep` 用法不当得出过错误数字（218），
   并在后续自査中纠正为 76。**报出的每个数字都应当可复现**。
4. **降级取舍要服务于核心目标。** 放弃 Mermaid 是为了保住"离线可用"这一更高优先级的要求。
5. **改完数据类内容后，必须全仓库搜索旧值。** 否则会留下文档间自相矛盾（本次实验报告就曾残留 6 处）。
6. **自己能验证的事不要外包给用户。** 构建、链接、HTTP 状态码都可自行验证；
   只有需要账号凭据的操作（如推送 GitHub）才如实标注为未完成。
