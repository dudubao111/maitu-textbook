# 7.3 递推与贪心入门

## 一、递推：用"前一步的结果"推下一步

**递推（Recurrence）就是根据已知的前几项，按照固定规律推出后续项。**

它和我们第 6 章学的递归长得很像，但**实现方式完全不同**：

| 对比项 | 递归 | 递推 |
|---|---|---|
| 方向 | 从"大问题"往"小问题"走，再往回算 | 从"已知的小问题"往"大问题"推 |
| 实现 | 函数调用自己 | 用循环 + 变量保存中间结果 |
| 效率 | 低（有重复计算） | 高（每个结果只算一次） |

**一句话概括：递归是"从上往下展开"，递推是"从下往上累加"。**

## 二、最简单的递推：累加与累乘

```python title="recurrence_basic.py" linenums="1"
# 递推求 1 + 2 + ... + n
n = 100
total = 0
for i in range(1, n + 1):
    total = total + i          # 用前一步的 total 推出新的 total
print(f"1 到 {n} 的和是 {total}")

# 递推求 n!
n = 6
factorial = 1
for i in range(1, n + 1):
    factorial = factorial * i
print(f"{n}! = {factorial}")
```

**运行结果：**

```text
1 到 100 的和是 5050
6! = 720
```

!!! tip "递推的核心：想清楚"上一项"和"这一项"的关系"
    - 累加：`这一项和 = 上一项和 + 当前数`
    - 累乘：`这一项积 = 上一项积 × 当前数`

    把它们写成公式，就是**递推公式**。

## 三、经典案例：爬楼梯

> **问题**：一段楼梯有 n 级，每次可以走 1 级或 2 级。
> 走到顶端共有多少种不同的走法？

**分析**（这是递推思维的关键一步）：

想到达第 `n` 级，最后一步只有两种可能：

- 从第 `n-1` 级走 1 级上来；
- 从第 `n-2` 级走 2 级上来。

所以：**`f(n) = f(n-1) + f(n-2)`**

```text
n = 1 → 1 种（走 1 级）
n = 2 → 2 种（1+1 或 2）
n = 3 → f(2) + f(1) = 3 种
n = 4 → f(3) + f(2) = 5 种
n = 5 → f(4) + f(3) = 8 种
```

```python title="climb_stairs.py" linenums="1"
def climb_ways(n):
    """递推求爬 n 级楼梯的走法数"""
    if n <= 2:
        return n
    f1, f2 = 1, 2                # f1 = f(n-2)，f2 = f(n-1)
    for i in range(3, n + 1):
        f1, f2 = f2, f1 + f2     # 递推：新的 f(n) = f(n-1) + f(n-2)
    return f2

for i in range(1, 11):
    print(f"{i} 级楼梯有 {climb_ways(i)} 种走法")
```

**运行结果：**

```text
1 级楼梯有 1 种走法
2 级楼梯有 2 种走法
3 级楼梯有 3 种走法
4 级楼梯有 5 种走法
5 级楼梯有 8 种走法
6 级楼梯有 13 种走法
7 级楼梯有 21 种走法
8 级楼梯有 34 种走法
9 级楼梯有 55 种走法
10 级楼梯有 89 种走法
```

!!! success "为什么用递推而不是递归？"
    如果写成递归 `f(n) = f(n-1) + f(n-2)`，就是第 6 章那个"重复计算"的斐波那契，
    `n = 40` 时就要等很久。

    **递推版本只用两个变量保存前两项**，每个结果只算一次，`n = 100` 也是瞬间完成。
    **这就是"用递推消除重复计算"的典型范例。**

## 四、贪心：每一步都选"当前最好"的

**贪心算法（Greedy）的思路：不去通盘考虑全局最优，而是每一步都选眼前看起来最好的选择。**

它不保证对所有问题都得到最优解，但对**某些特定问题**恰好能。

### 经典案例：找零钱（最少硬币数）

> **问题**：用 1 元、2 元、5 元的硬币凑出 47 元，最少要用几枚硬币？

**贪心策略**：**每次尽量用面值最大的硬币。**

```python title="greedy_coins.py" linenums="1"
amount = 47
coins = [5, 2, 1]              # 面值从大到小
used = []

for coin in coins:
    count = amount // coin     # 这种硬币能用几枚
    if count > 0:
        used.append((coin, count))
        amount = amount % coin # 用掉后剩余的金额

total_coins = sum(c for _, c in used)
for coin, count in used:
    print(f"{coin} 元硬币 {count} 枚")
print(f"最少需要 {total_coins} 枚硬币")
```

**运行结果：**

```text
5 元硬币 9 枚
2 元硬币 1 枚
最少需要 10 枚硬币
```

（9 × 5 + 1 × 2 = 47，共 10 枚）

!!! warning "贪心不一定总是最优！"
    上面这个"找零钱"问题，面值是 1、2、5 时贪心恰好正确。
    但如果面值换成 1、3、4，找 6 元：

    | 策略 | 方案 | 硬币数 |
    |---|---|---|
    | 贪心（先拿 4） | 4 + 1 + 1 | 3 枚 |
    | 最优解 | 3 + 3 | **2 枚** |

    **贪心在这里就错了。** 所以使用贪心前，必须能**证明**"每一步选最好就能得到全局最好"。

### 另一个例子：活动安排（区间调度）

> **问题**：一天中有若干活动，每个活动有开始和结束时间，同一时间只能参加一个。
> 如何安排参加最多活动？

**贪心策略**：**每次选"结束时间最早"且与已选活动不冲突的。**

```python title="activity_selection.py" linenums="1"
# 每个活动表示为 (开始, 结束)
activities = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9), (6, 10), (8, 11), (8, 12), (2, 14), (12, 16)]

# 按结束时间升序排序
activities.sort(key=lambda x: x[1])

selected = []
last_end = 0
for start, end in activities:
    if start >= last_end:          # 与上一个已选活动不冲突
        selected.append((start, end))
        last_end = end

print("最多可以参加的活动：")
for s, e in selected:
    print(f"  {s} 点到 {e} 点")
print(f"共 {len(selected)} 个活动")
```

**运行结果：**

```text
最多可以参加的活动：
  1 点到 4 点
  5 点到 7 点
  8 点到 11 点
  12 点到 16 点
共 4 个活动
```

!!! success "这道题贪心能得最优解"
    "每次选结束时间最早的活动"这个策略，可以**证明**是正确的：
    结束得越早，留给后面活动的时间越多。
    这类"可证明正确"的贪心，是竞赛中非常常见的题型。

## 本章小结

!!! abstract "第 7 章 小结"
    **1. 枚举法。** 三要素：枚举对象、枚举范围、判断条件。
    优化手段是**用约束减少维度**和**剪枝缩小范围**。可能性有限时才可用。

    **2. 查找。** 顺序查找 O(n)，不要求有序；
    二分查找 O(log n)，**前提是数据有序**，注意循环条件与边界更新（写错会死循环或漏解）。

    **3. 排序。** 冒泡排序（相邻比较交换，可用 `swapped` 提前结束）、
    选择排序（每轮选出最小值）。
    但实际比赛应用内置的 `sorted()` / `sort()`。

    **4. 递推。** 从小规模往大规模推，用几个变量保存中间结果，
    **能消除递归的重复计算**。经典例子：斐波那契、爬楼梯。

    **5. 贪心。** 每步选"当前最好"，代码简单、效率高，
    但**不保证全局最优**——使用前必须能说明它为什么正确。
    经典例子：找零钱、活动安排。

    **6. 效率意识。** 用 O(1)、O(n)、O(n²)、O(log n) 粗略衡量算法快慢；
    根据题目给出的数据范围反推该用什么算法。

## 练习与参考

!!! question "练习 1（枚举）"
    用枚举法求 1 到 100 之间所有**能被 3 整除或能被 5 整除**的数的和。

    ??? success "参考答案与评价要点"

        ```python
        total = 0
        for i in range(1, 101):
            if i % 3 == 0 or i % 5 == 0:
                total += i
        print(total)
        ```

        结果：`2418`

        评价要点：正确使用 `or`（40 分）；范围正确（30 分）；结果正确（30 分）。

!!! question "练习 2（查找）"
    二分查找为什么要求数据有序？如果对无序数据使用二分查找会发生什么？

    ??? success "参考答案与评价要点"
        **原因**：二分查找的核心是"根据中间元素与目标的大小关系，判断目标在哪一半"。
        如果数据无序，中间元素的大小**无法说明目标在左还是右**，判断就失去依据。

        **后果**：程序**不会报错**，但会返回错误结果（明明存在却找不到，或找到错误位置）。
        这类"不报错的错误"最危险。

        评价要点：能说明"大小关系失去意义"即得满分（100 分）。

!!! question "练习 3（排序）"
    用冒泡排序对 `[4, 2, 7, 1, 3]` 进行升序排列，
    **写出第一轮结束后的结果**。

    ??? success "参考答案与评价要点"
        **第一轮后：`[2, 4, 1, 3, 7]`**

        过程：比较 4 和 2（交换 → 2,4,7,1,3）→ 比较 4 和 7（不换）→
        比较 7 和 1（交换 → 2,4,1,7,3）→ 比较 7 和 3（交换 → 2,4,1,3,7）。
        **最大的 7 冒到了末尾。**

        评价要点：结果正确得 100 分；过程叙述清楚额外说明理解到位。

!!! question "练习 4（递推）"
    一个数列：`1, 2, 4, 7, 11, 16, ...`（相邻两项之差依次为 1, 2, 3, 4, 5）。
    请写出它的递推关系，并求出第 20 项。

    ??? success "参考答案与评价要点"
        **递推关系**：`f(n) = f(n-1) + (n-1)`，且 `f(1) = 1`

        ```python
        def seq(n):
            f = 1
            for i in range(2, n + 1):
                f = f + (i - 1)
            return f
        print(seq(20))    # 191
        ```

        结果：`f(20) = 1 + (1+2+...+19) = 1 + 190 = 191`

        评价要点：递推关系正确（50 分）；结果正确（50 分）。

!!! question "练习 5（贪心）"
    有 5 件物品，占用空间分别为 `[2, 3, 4, 5, 6]`，
    现有大小分别为 `10, 8` 的两个箱子。用贪心策略（大物品先放宽箱）能否装下？
    请写出装箱过程并给出结论。

    ??? success "参考答案与评价要点"
        **按从大到小排序**：6, 5, 4, 3, 2

        - 6 装入箱子 10（剩余 4）
        - 5 放不进箱子 10（放不下），装入箱子 8（剩余 3）
        - 4 刚好装满箱子 10（剩余 0）
        - 3 装入箱子 8（剩余 0）
        - 2 **装不下**（两个箱子都满了）

        **结论：装不下全部 5 件，最多装 4 件。**

        评价要点：装箱过程清晰正确（60 分）；
        结论正确（20 分）；能指出"贪心不保证最优，但本题已达到该策略下的最好结果"（20 分）。
