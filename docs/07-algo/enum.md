# 7.1 枚举法：一个一个试

## 一、什么是枚举法

**枚举法（穷举法）就是把所有可能的答案逐一试一遍，从中找出符合要求的那些。**

它听起来很"笨"，但却是最可靠的方法之一——**只要可能性是有限的，枚举就不会漏解。**
对初学者来说，枚举是解竞赛题最重要的"保底武器"。

**枚举的三要素：**

| 要素 | 要问的问题 |
|---|---|
| 枚举对象 | 我要逐个试的是什么？（一个数？一对数？一种排列？） |
| 枚举范围 | 从几试到几？边界是否包含？ |
| 判断条件 | 什么样的答案才算"符合要求"？ |

## 二、最简单的枚举：一重循环

> **问题**：找出 100 到 200 之间所有能被 7 整除的数。

```python title="enum_basic.py" linenums="1"
for n in range(100, 201):      # 枚举范围：100 到 200
    if n % 7 == 0:             # 判断条件
        print(n, end=" ")
print()
```

**运行结果：**

```text
105 112 119 126 133 140 147 154 161 168 175 182 189 196
```

**三要素对照：**

- 枚举对象：整数 `n`
- 枚举范围：`range(100, 201)`（注意包含 200）
- 判断条件：`n % 7 == 0`

## 三、双重循环枚举

> **问题**：鸡兔同笼。头共 35 个，脚共 94 只，问鸡兔各几只？

**枚举思路**：假设鸡有 `x` 只，兔有 `y` 只。`x + y = 35`，那 `y` 可以直接由 `x` 算出，
所以其实**只需要枚举一个变量**：

```python title="chicken_rabbit.py" linenums="1"
total_head = 35
total_feet = 94

for chicken in range(0, total_head + 1):     # 鸡的数量可能是 0 到 35
    rabbit = total_head - chicken            # 兔的数量由鸡决定
    if chicken * 2 + rabbit * 4 == total_feet:
        print(f"鸡有 {chicken} 只，兔有 {rabbit} 只")
```

**运行结果：**

```text
鸡有 23 只，兔有 12 只
```

!!! success "一个关键的优化思路"
    如果写成**双重循环**（鸡和兔都从 0 枚举到 35），要试 36 × 36 = 1296 次。
    但我们发现 **`y = 35 - x`**，所以减少成**一重循环**，只要试 36 次。

    **"用已知的约束减少枚举的维度"** 是枚举法最重要的优化技巧。

## 四、枚举 + 剪枝

> **问题**：找出 1 到 1000 之间的所有"水仙花数"（3 位数，各位数字的立方和等于它本身）。

```python title="narcissistic.py" linenums="1"
for n in range(100, 1000):            # 水仙花数都是三位数，直接从 100 开始
    hundreds = n // 100
    tens = (n // 10) % 10
    units = n % 10
    if hundreds ** 3 + tens ** 3 + units ** 3 == n:
        print(n)
```

**运行结果：**

```text
153
370
371
407
```

!!! tip "这就是"剪枝""
    - 如果把范围写成 `range(1, 1001)`，会多试 100 个无意义的数；
    - 写成 `range(100, 1000)`，直接跳过了不可能是三位数的部分。

    **剪枝 = 提前排除掉明显不可能的选项，缩小枚举范围。**
    这通常是让一个"超时"的程序变成"通过"的关键。

## 五、枚举的局限：什么时候不能用

枚举的前提是**可能性有限**。如果可能性太多，枚举会超时。

| 数据范围 | 双重循环（O(n²)）运算次数 | 能否接受 |
|---|---|---|
| n = 100 | 约 1 万次 | ✅ 轻松 |
| n = 1000 | 约 100 万次 | ✅ 可以 |
| n = 10000 | 约 1 亿次 | ⚠️ 偏慢，可能超时 |
| n = 100000 | 约 100 亿次 | ❌ 必然超时 |

!!! warning "经验值"
    一般来说，一个程序**每秒大约能执行 1000 万到 1 亿次**简单运算。
    竞赛题如果给出 `n ≤ 1000`，通常暗示"O(n²) 可以过"；
    如果给出 `n ≤ 100000`，那就要找 O(n) 或 O(n log n) 的算法了。

## 六、案例分析：找零钱问题

> **问题**：用 1 元、2 元、5 元的硬币凑出 11 元，共有多少种不同的凑法？
> （不考虑顺序，即 1+5+5 和 5+1+5 算同一种）

**分析**：三个未知数，但可以**用约束减少一维**：

```text
设 5 元用 a 枚，2 元用 b 枚，剩下的由 1 元补足
1 元硬币数量 = 11 - 5a - 2b，必须 ≥ 0
```

```python title="coin_change.py" linenums="1"
target = 11
count = 0

for a in range(0, target // 5 + 1):          # 5 元最多 2 枚
    for b in range(0, target // 2 + 1):      # 2 元最多 5 枚
        rest = target - 5 * a - 2 * b        # 剩下的用 1 元补
        if rest >= 0:
            count += 1
            print(f"5元{a}枚 + 2元{b}枚 + 1元{rest}枚")

print(f"共有 {count} 种凑法")
```

**运行结果（节选）：**

```text
5元0枚 + 2元0枚 + 1元11枚
5元0枚 + 2元1枚 + 1元9枚
...
5元2枚 + 2元0枚 + 1元1枚
共有 10 种凑法
```

!!! success "这个案例的两个要点"
    1. **用约束减少循环层数**：本来三个未知数要三重循环，但第三个可以由前两个算出来，
       所以只用两重循环；
    2. **循环上界要算清楚**：`5 元最多 target // 5 枚`，而不是盲目写一个大数。
       算清上界既是效率优化，也避免无效枚举。

## 七、实践任务 7-1：找素数对

!!! example "任务说明"
    **输入**：一个正整数 `n`。
    **操作要求**：找出所有满足 `a + b = n` 且 `a`、`b` 都为素数的数对（`a ≤ b`）。
    **预期结果**：输入 `20`，输出 `3 + 17`、`7 + 13`（因为 3、7、13、17 都是素数）。
    **评价标准**：
    - 能正确枚举并判断素数（50 分）
    - 保证 `a ≤ b`，不输出重复对（20 分）
    - 枚举范围合理（只需枚举到 n//2）（20 分）
    - 代码清晰、有注释（10 分）

## 八、实践任务 7-2：百钱买百鸡

!!! example "任务说明"
    **背景**：公鸡 5 元一只，母鸡 3 元一只，小鸡 1 元三只；
    用 100 元买 100 只鸡，问公鸡、母鸡、小鸡各多少只？
    **操作要求**：
    1. 用枚举法求解（提示：小鸡数量 = 100 − 公鸡 − 母鸡）；
    2. 输出所有可能的组合。
    **预期结果**：共有 4 组解（如 `公鸡 0 母鸡 25 小鸡 75` 等）。
    **评价标准**：
    - 能正确列出约束条件（`5a + 3b + c/3 = 100`，`a+b+c = 100`）（50 分）
    - 能减少枚举维度（只枚举公鸡和母鸡）（30 分）
    - 程序可运行、结果正确（20 分）
