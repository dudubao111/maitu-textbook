# 8.1 读题、建模与调试

## 一、五步解题流程

比赛时最怕"上来就写代码"。请严格按下面的顺序走——**想清楚的时间，永远比改代码的时间短。**

| 步骤 | 做什么 | 产出 |
|---|---|---|
| **① 读题** | 通读全文，圈出数据范围、输入格式、输出格式 | 标注过的题面 |
| **② 样例分析** | 手动模拟第一个样例，验证自己理解得对不对 | 手算过程 |
| **③ 建模** | 把题目转成"输入—处理—输出"，选定算法 | 算法思路 |
| **④ 编码** | 把算法翻译成代码，边写边注释 | 可运行程序 |
| **⑤ 自测提交** | 用样例、边界、大数据测试，通过后提交 | 提交结果 |

!!! warning "最容易忽略的是第 ② 步"
    **手动把样例算一遍**，能立刻暴露"理解错了"这类致命问题。
    如果连样例都算不出题目的答案，代码写得再漂亮也是错的。

## 二、读题时要圈出什么？

拿到题目，用笔圈出这五类信息：

| 类别 | 例子 | 为什么重要 |
|---|---|---|
| **数据范围** | `1 ≤ n ≤ 100000` | 决定算法复杂度，防止超时 |
| **输入格式** | "第一行一个整数 n，第二行 n 个整数" | 决定怎么读数据 |
| **输出格式** | "输出一行，保留两位小数" | 决定怎么输出，直接影响得分 |
| **特殊情况** | "如果不存在，输出 -1" | 漏掉就直接错 |
| **时间/内存限制** | "时间限制 1000 ms" | 判断算法是否够快 |

!!! tip "一个高频陷阱：数据范围决定算法"
    | 数据范围 | 通常暗示 |
    |---|---|
    | `n ≤ 100` | 三重循环 O(n³) 也行 |
    | `n ≤ 1000` | O(n²) 可以 |
    | `n ≤ 10⁵` | 需要 O(n log n) 或 O(n) |
    | `n ≤ 10⁶` | 必须接近 O(n)，且注意读写效率 |

    **先看范围，再想算法**，能避免"写完才发现超时"的悲剧。

## 三、建模：从题目到算法

用下面的问题完整走一遍流程。

!!! info "题目"
    **统计及格人数**
    输入 `n` 个学生的成绩（0 到 100 的整数），输出及格（≥ 60 分）的人数。
    第一行是 n，第二行是 n 个整数。

**第 ① 步：读题**

- 数据范围：题目未特别说明，假设 `1 ≤ n ≤ 1000`
- 输入格式：第一行 n，第二行 n 个数
- 输出格式：一个整数

**第 ② 步：样例分析**（自己造一个）

```text
输入：
5
88 45 60 59 100

手算：及格的有 88、60、100 → 共 3 人
```

**第 ③ 步：建模**

```text
输入：n 和 n 个成绩
处理：遍历每个成绩，如果 ≥ 60 就让计数器加 1
输出：计数器
```

**第 ④ 步：编码**

```python title="pass_count.py" linenums="1"
n = int(input())                        # 第一行：人数
scores = list(map(int, input().split()))  # 第二行：n 个成绩

count = 0
for s in scores:
    if s >= 60:
        count += 1

print(count)
```

**第 ⑤ 步：自测**

```text
输入：5 / 88 45 60 59 100   → 输出 3 ✅
边界：1 / 59                → 输出 0 ✅
边界：3 / 60 60 60          → 输出 3 ✅
```

## 四、调试：程序不对怎么办

### 方法 1：打印调试法（最实用）

在关键位置插入 `print`，看看变量到底是多少。

```python
scores = list(map(int, input().split()))
print("DEBUG: 读到的成绩 =", scores)      # 确认读入正确

count = 0
for s in scores:
    print(f"DEBUG: 检查 {s}, 是否及格 = {s >= 60}")   # 看判断是否正确
    if s >= 60:
        count += 1
    print(f"DEBUG: 当前 count = {count}")             # 看累加是否正确

print(count)
```

!!! tip "调试的三条纪律"
    1. **先确认输入对不对**——很多错误其实出在"数据没读进来"；
    2. **二分定位**——在程序中点打印，判断错误在前半段还是后半段；
    3. **调试语句提交前必须删掉**——否则会污染输出，直接导致格式错误！

### 方法 2：小数据手推

用最小的数据（如 n = 1、2）手动推演，和程序输出对比，找出第一处不一致的地方。

### 方法 3：对照法

用 Python 内置函数验证自己的实现：

```python
data = [3, 1, 4, 1, 5]
print("我的结果：", my_sort(data))
print("标准结果：", sorted(data))     # 对比验证
```

## 五、常见的五类错误

| 错误类型 | 英文缩写 | 常见原因 | 排查方向 |
|---|---|---|---|
| **答案错误** | WA | 逻辑错、边界没处理、理解错题意 | 用小数据手推，检查边界 |
| **超时** | TLE | 算法太慢、循环次数太多 | 看数据范围，换更优算法 |
| **运行时错误** | RE | 数组越界、除零、递归过深 | 检查下标范围、终止条件 |
| **格式错误** | PE | 多空格、少换行、大小写不符 | 严格对照输出格式 |
| **编译错误** | CE | 语法错误（C++ 常见） | 读错误信息第一行 |

!!! danger "格式错误最"冤""
    - 题目要求"每行一个"，你输出了"一行多个"→ 错；
    - 题目要求"输出 `Yes`/`No`"，你输出了 `YES`/`NO` → 错；
    - 题目要求"保留两位小数"，你输出了 `3.5` 而不是 `3.50` → 错。

    **提交前，逐字对照题目的输出格式。** 这一步只要 10 秒，能救回很多分。

## 六、实战案例：从错误到正确

!!! failure "一个有 bug 的程序"
    题目：输入 n 个数，输出其中的最大值。

    ```python
    n = int(input())
    nums = list(map(int, input().split()))

    max_val = 0              # ❌ 有问题！
    for x in nums:
        if x > max_val:
            max_val = x
    print(max_val)
    ```

    **问题在哪？** 如果输入全是负数，比如 `3 / -5 -2 -8`，
    程序会输出 `0`——但 0 根本不在输入里！因为 `max_val` 初始值是 0，永远比负数大。

!!! success "正确的写法"
    ```python
    n = int(input())
    nums = list(map(int, input().split()))

    max_val = nums[0]        # ✅ 用第一个元素作为初始值
    for i in range(1, n):
        if nums[i] > max_val:
            max_val = nums[i]
    print(max_val)
    ```

    **或者直接用内置函数**（比赛推荐）：
    ```python
    print(max(nums))
    ```

!!! success "这个案例的教训"
    **初始值的选择要考虑"极端情况"。** 找最大值时初始值应设为"比所有可能值都小"，
    或者干脆用第一个元素。**边界测试（全负数、全相同、只有一个元素）是必须做的。**

## 七、实践任务 8-1：调试练习

!!! example "任务说明"
    **背景**：下面程序想求 1 到 n 中所有奇数的和，但有 bug。

    ```python
    n = int(input())
    total = 0
    for i in range(1, n):
        if i % 2 == 1:
            total += i
    print(total)
    ```

    **操作要求**：
    1. 找出 bug 并说明原因；
    2. 修正后用 `n = 5` 验证（正确答案是 1+3+5 = 9）。
    **预期结果**：修正后输入 `5` 输出 `9`。
    **评价标准**：
    - 能定位到 `range(1, n)` 少了 n（30 分）
    - 能说明 `range` 左闭右开（30 分）
    - 修正后结果正确（40 分）
