# 2.2 问题分解与抽象

## 一、拿到一个问题，先做三件事

很多同学看到题目就急着写代码，结果写到一半发现"方向不对"。请养成一个固定动作：
**先做"输入 — 处理 — 输出"三步分析**。

| 步骤 | 要问自己的问题 | 举例：算购物总价 |
|---|---|---|
| **输入** | 我手上有什么数据？从哪来？ | 单价 12.5 元、数量 3 件、折扣 0.9 |
| **处理** | 要对数据做什么运算或判断？ | 单价 × 数量 → 再 × 折扣 |
| **输出** | 最后要给用户看什么？ | 一行文字："应付 33.75 元" |

把这个框架套上去，问题立刻从"一团乱麻"变成"一条流水线"。

```text
输入 ──► 处理 ──► 输出
(单价/数量/折扣)  (相乘)  (应付金额)
```

!!! tip "一个小习惯"
    在纸上画出这条流水线，**每画一个箭头就问一次"这一步的输入是什么、输出是什么"**。
    能画出来，就基本能写出来了。

## 二、分解的三个常用角度

同一个问题，可以从不同角度拆。这里介绍三种最常用的，**能解决 90% 的入门题**。

### 角度 1：按时间顺序拆（最常用）

适用于"有先后步骤"的问题，比如"先做 A，再做 B，最后做 C"。

```text
任务：制作一份成绩单
├── 第 1 步：读取所有成绩        （先要有数据）
├── 第 2 步：算出总分和平均分     （再计算）
├── 第 3 步：判断是否及格         （然后判断）
└── 第 4 步：按格式输出           （最后输出）
```

### 角度 2：按功能模块拆

适用于"一件大功能由几个小功能组成"的问题。

```text
任务：一个"猜数字"小游戏
├── 模块 A：生成一个随机数
├── 模块 B：读取玩家猜的数字
├── 模块 C：比较大小并给出提示
└── 模块 D：判断是否猜中、是否继续
```

**每个模块后面都可以写成一个函数（第 6 章）**，这就是"模块化"思想的起点。

### 角度 3：按数据类型拆

适用于"数据分成好几类，需要分别处理"的问题。

| 数据类型 | 处理方式 |
|---|---|
| 整数（人数、个数） | 整数运算 |
| 小数（价格、成绩） | 小数运算，注意精度 |
| 文字（姓名、科目名） | 字符串处理（第 5 章） |

## 三、抽象：把"多余的东西"扔掉

**抽象的正式定义：只保留与解决问题相关的特征，忽略其余细节。**

我们来看一个"抽象"的过程。任务是：**判断一名学生能否参加某比赛。**

=== "抽象前（信息太多）"
    - 姓名：李小明
    - 性别：男
    - 身高：165 cm
    - 喜欢的颜色：蓝色
    - 出生年月：2013 年 5 月
    - 就读学校：湛江某中学
    - 学段：初二
    - 喜欢的科目：数学
    - 比赛日期：2026 年 9 月

=== "抽象后（只留关键）"

    判断"能否参加"，真正需要的只有两条：

    - **出生年月**（决定是否满 12 周岁）
    - **学段 / 学籍**（决定是否符合面向学段）

    其余信息（身高、颜色、喜欢的科目）**与问题无关，全部丢弃**。

!!! success "抽象的收益"
    抽象之后，你的程序只需要处理 2 个数据的判断，而不是 9 条杂乱信息。
    **信息越少，程序越不容易出错。**

## 四、画一张"流程图"（用文字也能画）

算法步骤写完后，建议画一张流程图来检查逻辑。没有专业工具也没关系，
**用文字 + 箭头**一样能表达清楚：

```text
        ┌──────────────┐
        │  开始        │
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │ 输入 单价、数量│
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │ 总价 = 单价×数量│
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │ 输出 总价     │
        └──────┬───────┘
               ▼
        ┌──────────────┐
        │  结束        │
        └──────────────┘
```

## 五、案例分析：从题目到算法

!!! info "题目"
    一支铅笔单价 12.5 元，小明买了 3 支，店家搞活动全场九折。
    请计算出小明实际需要支付多少钱。

**第一步：输入 — 处理 — 输出分析**

| 环节 | 内容 |
|---|---|
| 输入 | 单价 = 12.5，数量 = 3，折扣 = 0.9 |
| 处理 | 原价 = 单价 × 数量；应付 = 原价 × 折扣 |
| 输出 | 一句话说明应付金额 |

**第二步：分解**

```text
① 记下单价和数量
② 算出原价 = 单价 × 数量
③ 算出应付 = 原价 × 折扣
④ 输出应付金额
```

**第三步：翻译成代码（完整可运行）**

```python title="shopping.py" linenums="1"
# 案例：计算打折后的应付金额
# 输入
price = 12.5      # 单价（元）
count = 3         # 数量（支）
discount = 0.9    # 折扣（九折）

# 处理
original = price * count      # 原价
pay = original * discount     # 折后应付

# 输出
print("原价：", original, "元")
print("应付：", pay, "元")
```

**运行结果：**

```text
原价： 37.5 元
应付： 33.75 元
```

!!! warning "注意小数"
    计算机中的小数有时会出现 `33.750000000000004` 这样的"尾巴"，
    这是浮点数的正常现象（第 3 章会解释原因）。本教材示例中出现的都是精确结果。

## 本章小结

!!! abstract "第 2 章 小结"
    **1. 计算思维四要素**：分解（拆问题）、模式识别（找规律）、抽象（去细节）、算法（写步骤）。

    **2. 三步分析法**：任何问题先问"输入是什么、要处理什么、输出什么"，把它变成一条流水线。

    **3. 分解的三个角度**：按时间顺序、按功能模块、按数据类型。选对角度，问题瞬间变简单。

    **4. 抽象是减法**：只留与解决问题相关的信息，把无关细节果断丢掉。

    **5. 先设计、后编码**：算法用自然语言写清楚，代码只是"翻译"。
