    2.1 计算思维的四个关键词¶

    一、什么是计算思维¶

    **计算思维（Computational Thinking）**不是"学计算机的思维"，而是 面对一个问题时，用计算机能理解的方式把它想清楚、说明白的能力。

    它由四个关键词组成，我们用一个具体任务来逐个体验： "帮班主任算出一个班 45 名同学的数学平均分。"

    关键词 英文 通俗解释 在这个任务里
    分解 Decomposition 把大问题拆成小问题 拆成：收集分数 → 求和 → 除以人数
    模式识别 Pattern Recognition 找出重复出现的规律 45 个分数，处理方式是同一个：加到一起
    抽象 Abstraction 去掉无关细节，只保留关键 "张三还是李四"不重要，分数才重要
    算法 Algorithm 把解决步骤写成清晰的顺序 ①分数加总 → ②除以 45 → ③输出结果

    二、逐个展开¶

    1. 分解：大问题 → 小问题¶

    面对"算平均分"，如果你盯着"45 个人怎么算"发愁，就会卡住。 但只要拆开，每一步都变得简单：

    算全班数学平均分
├── 第 1 步：收集 45 个数学分数
├── 第 2 步：把所有分数加在一起 → 得到总分
├── 第 3 步：总分 ÷ 45 → 得到平均分
└── 第 4 步：把结果打印出来

    分解的诀窍

    如果某一步你还不知道怎么写代码，说明它拆得还不够细。 继续拆，直到每一步都简单到"看标题就知道怎么做"为止。

    2. 模式识别：找出重复的规律¶

    班里 45 个分数，处理方法完全一样——"把它们加起来"。 识别出这种重复，就意味着可以用循环（第 4 章）一次搞定，而不用写 45 行代码。

    再举个例子：

    场景 你看到的规律 对应到编程
    输入 45 个分数 每个分数的处理方式相同 循环 45 次
    判断每个分数是否及格 判断条件相同（是否 ≥ 60） 分支结构

    3. 抽象：去掉无关细节¶

    "抽象"听起来很玄，其实就是只保留对解决问题有用的信息。

    在"算平均分"这件事里：

    信息 是否需要 原因
    学生的姓名 ❌ 不需要 平均分只和分数有关
    学生的座位号 ❌ 不需要 同上
    每门课的分数 ✅ 需要 这是计算的数据来源
    科目名称 ⚠️ 视情况 如果只算数学就不用

    抽象做得好，问题会瞬间变简单。 你不需要管理 45 个"人"，只需要管理 45 个"数字"。

    4. 算法：写成清晰的步骤¶

    算法 = 解决问题的有限步骤序列。 它的特点是有明确的顺序、每一步都可执行、 有限步之后就结束。上面那个任务的算法就是：

    输入：45 个数学分数
处理：
  ① 令 总分 = 0
  ② 对每一个分数 f：总分 = 总分 + f
  ③ 平均分 = 总分 ÷ 45
输出：平均分

    # 用计算思维解决"算平均分"
# 抽象：只关心分数，不关心是谁的分数
chinese = 88
math = 92
english = 85

# 分解第一步：求和（模式识别：三个分数相加是同一个操作）
total = chinese + math + english

# 分解第二步：除以科目数
average = total / 3

# 输出结果
print("总分：", total)
print("平均分：", average)

    先看结构，别纠结语法

    现在你不需要看懂每一行。请重点体会：代码的顺序，和上面算法的顺序是一一对应的。 这就是"算法 → 代码"的翻译过程。第 3 章开始，我们会把这些语法逐条讲清。

    四、计算思维不是编程专利¶

    这四个关键词在生活中到处都在用：

    场景 分解 模式识别 抽象 算法
    整理书包 拆成 备课本/备文具/备作业 每天都要备 只带当天要用的 按课表逐科打包
    做一道大题的解题步骤 拆成小问 同类题用同样方法 忽略无关条件 写出解题步骤
    上学路上选路线 拆成 家→站→校 每段都"选最快" 忽略路边的店铺 先选车次，再到校

    所以，学计算思维不只是在学编程，而是在学一种更清晰地想事情的方式。
